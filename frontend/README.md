# sage.ai — frontend

Next.js (App Router, TypeScript, Tailwind 4, Recharts) client for the sage.ai demo:
story (adoption chart + credibility strip) → bids → watch the coordinator (three acts, Beat the
coordinator) → results (strategy comparison, herding gap, avoided-carbon receipts with
leave-the-coalition toggles). It talks only to the backend API contract in `docs/design.md` (B6);
`src/lib/types.ts` mirrors `backend/clearinghouse/schemas.py`.

## Run against the backend (default)

```bash
# 1. backend, from the repo root (serves http://localhost:8000)
cd backend && uv run uvicorn clearinghouse.api:app --port 8000

# 2. frontend, in another shell
cd frontend && npm install && npm run dev   # http://localhost:3000
```

The backend allows CORS from `http://localhost:3000` and `http://127.0.0.1:3000` (more origins via
`FRONTEND_ORIGINS` in the backend environment). If the backend is not reachable the app shows an
error with a Retry button; a failed run keeps every input so you can re-run once it is back.

From Claude Code, the `.claude/launch.json` configs `backend` (:8000) and `frontend` (:3000) start
the same two servers.

## Environment variables

Both are read at build time (`NEXT_PUBLIC_*`), so restart `npm run dev` or rebuild after changing them.

| Variable | Default | Meaning |
|---|---|---|
| `NEXT_PUBLIC_API_MODE` | `live` | `live` calls the backend; `fixture` serves recorded responses (below). |
| `NEXT_PUBLIC_API_BASE` | `http://localhost:8000` | Backend origin used in live mode. |

## Fixture mode

```bash
NEXT_PUBLIC_API_MODE=fixture npm run dev
```

Serves the JSON in `src/fixtures/`: real backend responses for the example scenario, regenerated by
`backend/scripts/regenerate_fixtures.py` into the repo's `fixtures/` and copied here by
`scripts/sync-fixtures.mjs` before every `dev` / `build`. Every clear returns the recorded example
response whatever you enter, and Beat the coordinator returns the recorded score of a flat hand
schedule. The header shows a "Fixture mode — recorded data" badge and each screen says when a
number is a recording.

The sync script also copies `backend/data/processed/adoption_chart_meta.json` (population size,
draws, day) so the adoption chart caption can say how the chart was computed; the API contract
does not carry that metadata.

## Where numbers come from

Every number on screen comes from an API response or is computed in the browser from one; each
panel has a `source` line naming the field. Explanations of zero or tied results (for example, load
absorbed by curtailed renewables, or the planning-time fallback) are built from the same response,
never hard-coded.
